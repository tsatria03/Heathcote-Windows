# CLAUDE.md

This file guides Claude Code when it works in this repository. **It is a lean dispatcher.** It says what the project is and how it is laid out, then points to focused memory files (`[[name]]`) for the detail. When you start work in an area, read its linked memory first.

**Memory location:** all memory files (the `[[name]]` links and the `MEMORY.md` index) live in the repo's **`aidocks/`** folder, in two folders. **`aidocks/plans/`** holds every plan, planned or complete, as `aidocks/plans/<name>_plan.md` with no `project_` prefix; a finished plan stays there, marked finished. **`aidocks/general/`** holds every other note, as `aidocks/general/<name>.md`. A `[[name]]` link resolves to whichever of the two holds it ([[feedback_completed_projects]]). Read memory from there and write new or updated memory there, never to the `~/.claude` memory store. `aidocks/general/MEMORY.md` is the index, so add a one-line pointer there for every new memory. Keep this file under 40,000 characters and move detail into memory ([[feedback_memory_in_aidocks]]).

## What this is

A Windows port of **Heathcote** (`com.fabulaeobscurae.heathcote` 1.01, Fabulae Obscurae), an iOS interactive audio adventure "told through sound". The player follows a presenter exploring an abandoned asylum while on the phone to his producer, choosing what he does next from an actions menu. The original was played by swipes; the port is for the keyboard and screen readers.

- **A solo project.** tsatria03 makes it alone ([[project_solo]]).
- **Windows only** ([[project_windows_only]]).
- **Python only**, with pygame for the window and keys, FMOD through pyfmodex for all sound ([[project_fmod]]), and Prism and the NVDA client for speech ([[project_python_only]]).
- **No downloads.** Every recording ships with the game ([[project_no_downloads]]).
- **Developer tasks**, open and finished, are in [[project_dev_tasks]].
- **The game is data-driven.** The story is JSON exported from the original's authoring tool: choices with conditions, recordings ("spiels") that set variables at timed points and chain on, and ambience and music lanes with timed fades. What the data, the binary and the original's behaviour say is in [[project_original_findings]].
- **Status:** plan 1, reading the original, is finished ([[reading_original_plan]]): the tools, the readable script and [[project_original_behaviour]]. Plan 2, the foundation, is finished ([[foundation_plan]]). Plan 3, the audio, is finished ([[audio_plan]]). Plan 4, the story engine, is finished ([[story_engine_plan]]): the story plays from start to end by the original's rules. Plan 5, the menus, is finished ([[menus_plan]]): the opening, the main menu with the title music, Credits, the pause menu with Restart story and Continue story, and the end credits. Plan 6, the saves, is finished ([[saves_plan]]): the progress kept between runs, and Continue story from the save at the start of the spiel the player was in. Plan 7, building and releasing, is finished ([[build_release_plan]]): `compiler.py`, `releaser.py`, and the story's recordings in an encrypted `data\story.dat` beside the exe. ## Layout

- **`game/`**: the original app bundle, reorganized by the dev, and never written to by Claude. The layout is in [[project_original_findings]]. The story records are in `game/documents/text/story/`, with the master index `game/documents/text/system/Heathcote v1.01.bundle.json`. The recordings are all MP3, in `game/documents/Audio/story/` in one folder per kind, each under its English name; the story data names them by id, and [[project_audio_names]] maps each name back to its id. Don't move, rename, convert or delete sound files unless the dev asks.
- **`Heathcote.py`**: the entry script, with the options, the logs and the crash file ([[foundation_plan]]).
- **`compiler.py`**: builds `dist\Heathcote-Windows` around `Heathcote.exe` with PyInstaller, a folder build or a single exe, with `--test` and `--dry-run`; it never zips or changes the repository. **`releaser.py`** checks, versions, files the changelog, builds through the compiler, zips, commits, tags and uploads a release with `gh`, asking Y or N before each step. The dev runs both ([[build_release_plan]]).
- **`heathcote/`**: the port's Python package.
  - `paths.py`: the game data, the vendored DLLs, `VERSION` and the save folder.
  - `app.py`: the main loop, with F1, the volume keys and debug mode.
  - `platform/`: speech, the timer loop, safe JSON files, settings, the key map, `audio.py`, the FMOD side, `spiel.py`, the spiel with rewind and fast-forward, `lanes.py`, the four background lanes and the idle loop, and `pack.py`, `story.dat`, the story's recordings packed and encrypted for a build, played from memory. The key map's actions are grouped into menu, story, story volumes and title volume, by where they work.
  - `ui/`: the screen stack, the spoken menu, the F1 screen, Settings, and the spoken search, which debug mode's F3 uses.
  - `game/`: `storydata.py`, the one place the rules for reading the story data and finding recordings live, which `tools/story.py` imports; `state.py`, the story's variables, heard spiels and action counts; `player.py`, the story's rules played on the audio; `story_screen.py`, the story as a screen; `actions_menu.py`, the actions menu; `opening.py`, the police radio and the first-run notice; `menus.py`, the main menu, with Start story or Continue story; `credits.py`, the credits and the end credits; and `progress.py`, the story's progress between runs, `saves\progress.json`. The pause menu is in `story_screen.py`.
- **`tests/interact/`**: tools played by ear, not tests, run by the dev. `speech_check.py` tries the speech and the timer loop. `audio_check.py` plays the sound through FMOD, any spiel with its lanes. `story_check.py` plays the story by its rules, with keys to choose any spiel and hear its state. `menu_check.py` (renamed by the dev from `menus_check.py`, its save folder still `interact\menus_check`) runs the game from its opening, with Control keys to forget the notice, report the title music and the story, jump near the end, and clear the progress. Each tool keeps its own save under `%APPDATA%\Heathcote\interact\`. A tool for testing goes here, never into the game's menus ([[feedback_test_tools_in_interact]]).
- **`tests/case/`**: silent test scripts, each importing `_quiet.py` first, which keeps it silent and off the real save. `tests/suite.py` runs them all, or some by name, into the gitignored `tests/results/`. Run only the files covering what changed, in the background, and the full suite only when the dev asks ([[feedback_dont_run_or_build]]).
- **`vendor/nvda/`**: `nvdaControllerClient64.dll` (x64) and its license.
- **`vendor/fmod/`**: `fmod.dll` (FMOD Engine 2.02.35, x64), gitignored and copied in by hand from the FMOD install, and its licence, which is tracked ([[project_fmod]]).
- **`docks/`**: the documents a player reads: `readme.txt`, `changelog.txt` and `todo list.txt` ([[feedback_changelog]], [[feedback_todo_list_format]]). The readme describes only what works in the game now; bring it up to date as each plan lands.
- **`README.md`**: the developer's guide: status by plan, requirements, running, tests, layout, credits and licences. **`requirements.txt`**: `pygame`, `prismatoid`, `pyfmodex==0.7.2` and `cryptography`.
- **`analysis/`**: what the tools write from the original, for reference. `analysis/script/Heathcote.txt` is the whole story as plain text, written by `tools/script_text.py`; find "Spiel: <label>" to jump to a spiel.
- **`tools/`**: scripts for reading the original, described in `tools/README.md`. `macho64.py` and `dis64.py` read and disassemble `game/Heathcote` (not encrypted), citing the binary's own addresses; `story.py` reads and checks the story data the way the game will; `script_text.py` writes the script; `build_pack.py` makes `dist\story.dat` on its own, for a source run without the loose story folder.
- **`build/`** and **`dist/`**: build output, gitignored.
- **`user/`** is gitignored private reference material. Read it, but never edit it. Never name the dev's other games kept in it, in any of this repo's files ([[feedback_no_other_games]]).
- **`New File*.txt`** at the root is the dev's private scratchpad. It is gitignored; never read, edit, flag or delete it.

## Working here

- **The dev runs and builds, not Claude.** Ask before running the game or anything that plays sound or speaks ([[feedback_dont_run_or_build]]).
- **After each plan,** bring every developer doc, `aidocks/` included, and every player doc up to date, give a brief summary of the overall progress ([[feedback_progress_summary]]), then push ([[feedback_docs_after_each_plan]]).
- **Before each plan,** review it section by section with the dev, and build only on their word ([[feedback_review_plan_sections]]). Within a plan, when the dev says a section's tests passed, mark and commit it, then build the next section without asking ([[feedback_next_section_on_pass]]).
- **Before each section,** list what the dev will test by ear, sound or speech, each test marked optional or mandatory, and remind them of a mandatory test they haven't reported on ([[feedback_say_ear_tests_ahead]]).
- **Plans first:** an agreed plan goes into its own note in `aidocks/plans/` before any code, and is marked finished only once the dev says it works ([[feedback_record_plans_first]], [[feedback_completed_projects]]).
- **Committing and pushing:** commit finished work without asking; push only once a whole plan is finished and its docs are updated; "commit/push" means both; history rewrites need a go-ahead ([[feedback_git_commits]]). Name people by GitHub username only ([[feedback_use_github_usernames]]).
- **Questions:** a question from the dev is a check, answered in chat ([[feedback_questions_are_checks]]). Ask one question per reply, in plain text ([[feedback_one_question_at_a_time]], [[feedback_no_question_pickers]]).
- **Releases** are never recorded in notes or the README ([[feedback_no_release_records]]).
- **Menus:** Back is always the first row ([[feedback_back_first]]).
- **Who you're working with:** [[user_screen_reader]]. The dev uses NVDA, so prefer lists and short lines, never wide tables, and never make noise from tools.

`CLAUDE.md` and `aidocks/` are committed, not gitignored.
